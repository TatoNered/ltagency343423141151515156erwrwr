# LT Agency — сайт агентства

Статический сайт на трёх языках. Без зависимостей: нужен только Node 18+.
Тексты лежат в markdown, сборка выдаёт обычный HTML, который работает на любом хостинге.

```bash
node build.mjs            # собрать сайт в dist/
node build.mjs --serve    # собрать и открыть http://localhost:8080
node tools/analiza.mjs    # проверить тексты: тошнота, плотность, мета
```

---

## Что сделать перед публикацией

Найти по проекту строку `---POPUNITI---` и заменить везде:

```bash
grep -rn "POPUNITI" src/
```

Список того, что обязательно:

| Где | Что |
| --- | --- |
| `src/data/site.json` | название, домен, телефон, Viber, адрес, ссылки на Google-профиль и соцсети |
| `src/content/sr/kontakt.md` | телефон, почта, адрес, ПИБ, матичный номер, счёт |
| `src/content/ru/kontakt.md`, `en/contact.md` | то же |
| `src/content/sr/o-nama/tim.md` | реальные имена, годы опыта, фото, LinkedIn |
| `src/content/sr/rezultati/index.md` | письменное разрешение клиентов на упоминание |
| `src/assets/og.png` | картинка для соцсетей, 1200×630 |

Отдельно: **цифры в кейсах должны быть настоящими.** Сейчас там примеры из
переписки. Любой выдуманный результат — это то, что проверят в первую очередь.

## Как добавить страницу

Создать `.md` файл в нужной языковой папке. Путь файла = адрес страницы:
`src/content/sr/usluge/odrzavanje-sajta.md` → `/usluge/odrzavanje-sajta/`

```markdown
---
title: Заголовок для вкладки и выдачи, 35–60 символов
description: Описание для сниппета, 120–160 символов.
h1: Заголовок на странице
lede: Вводный абзац серым, одна-две фразы.
key: odrzavanje-sajta
crumb: Održavanje
toc: true
type: service
serviceName: Održavanje sajta
priceFrom: 60
---

Первый абзац — законченный ответ на вопрос страницы. Его забирают AI-ответы.

## Заголовок раздела
Текст.
```

Поля frontmatter:

- `key` — связывает версии на разных языках. Одинаковый `key` у сербской, русской
  и английской страницы → hreflang проставится сам. Нет пары — hreflang не ставится,
  и это правильно.
- `type: service` → в разметку добавится Service + Offer (нужен `priceFrom`).
- `type: article` → BlogPosting с автором. Нужны `date` и `author`.
- `toc: true` → оглавление по H2, если их больше двух.

## Что делается само

- hreflang и x-default по полю `key`
- Breadcrumbs: и видимые, и в разметке
- Schema: ProfessionalService, WebSite, BreadcrumbList, Service, FAQPage, BlogPosting
- **FAQ-разметка строится из самого текста.** Нужен раздел `## Česta pitanja`
  (или `## Частые вопросы` / `## FAQ`), а вопросы внутри — через `###`.
  Писать JSON руками не нужно.
- sitemap.xml с языковыми связями, robots.txt, 404
- `_headers` для Cloudflare Pages и Netlify

## Разметка в markdown

Обычный markdown плюс блоки:

```
:::note     выделенный блок с зелёной полосой
:::warn     предупреждение, оранжевая полоса
:::card     карточка
:::grid     сетка — каждый ### внутри станет отдельной карточкой
:::price    то же, для ценовых блоков
:::steps    нумерованные шаги (внутри — обычный список)
```

Закрываются одиночным `:::`.

## Анализатор текстов

```bash
node tools/analiza.mjs                      # все страницы
node tools/analiza.mjs /cene/               # одна
node tools/analiza.mjs --csv > analiza.csv  # выгрузка
```

Что считает и какие нормы:

| Показатель | Норма | Что значит |
| --- | --- | --- |
| Классическая тошнота | ≤ 7 | корень из повторов самого частого значимого слова |
| Академическая тошнота | ≤ 8 % | доля самого частого слова от всех слов |
| Вода | ≤ 60 % | доля стоп-слов |
| Плотность ключа | 0,5–3,2 % | ниже — фраза не закреплена, выше — переспам |
| title | 35–60 символов | дальше Google обрежет |
| description | 120–160 символов | |
| Объём | от 350 слов | для хабов и контактов порог ниже |

Плотность считается по основе слова, а не по точному совпадению — сербский
склоняется, и точный подсчёт занижал бы результат вдвое.

Целевые фразы по страницам заданы в объекте `TARGETS` в начале скрипта.
Добавляешь страницу — добавь туда её ключи.

## Публикация

Собранный `dist/` — обычные HTML-файлы. Работает везде.

**Обычный хостинг:** залить содержимое `dist/` в корень по FTP.

**Cloudflare Pages:** подключить репозиторий, команда сборки `node build.mjs`,
папка вывода `dist`. Файл `_headers` подхватится сам.

**После заливки проверить:**

1. `https://домен/sitemap.xml` открывается
2. `https://домен/robots.txt` открывается
3. Подтвердить домен в Google Search Console, отправить sitemap
4. Прогнать главную и `/cene/` через Rich Results Test — разметка должна читаться
5. Проверить, что `www` и без `www` не открываются оба (выбрать одно, второе — 301)

На обычном хостинге редиректы настраиваются в `.htaccess` или панели — генератор
их не делает, потому что это зависит от хостинга.

## Чего в проекте намеренно нет

- **JavaScript.** Ни строки. Мобильное меню на CSS. Это даёт скорость, которая
  для агентства по продвижению является аргументом.
- **Внешних шрифтов.** Системный стек: ноль запросов, ноль сдвига вёрстки.
- **AggregateRating в разметке.** Отзывы о себе на своём сайте Google не показывает
  с 2019 года и может выдать ручные санкции. Звёзды живут в Google-профиле.
- **HowTo-разметки.** Rich results под неё убраны, смысла нет.
- **Сборщиков и фреймворков.** Нечему ломаться при обновлениях.

## Если Node не установлен

В папке `site/` лежит **уже собранный сайт** — обычные HTML-файлы.
Ничего запускать не нужно: скопируй содержимое `site/` в корень хостинга
(`public_html`, `www` или как он называется у провайдера) и сайт работает.

Эта папка пересобирается командой `node build.mjs` и копированием `dist/` в `site/`.
Если правишь тексты — правь в `src/`, а не в `site/`: при следующей сборке
`site/` перезаписывается.

### Поставить Node (нужен для пересборки)

- **Windows / macOS:** скачать LTS с nodejs.org, установить, перезапустить терминал
- **Проверить:** `node -v` должно показать v18 или выше

Если `node -v` пишет «не является внутренней командой» или «command not found» —
Node либо не установлен, либо не попал в PATH. На Windows это чинится
переустановкой с галочкой «Add to PATH».

### Как запускать

```bash
cd путь/к/папке/с/build.mjs
node build.mjs
```

Самая частая ошибка — запуск не из той папки. `build.mjs` должен лежать
в текущей папке, проверь командой `ls` (macOS/Linux) или `dir` (Windows).
